# Why is Kiro CLI so fat?

This is just a very quick look at the `kiro-cli` binary, which is allegedly written in Rust.

First we need to "install" the kiro CLI.

If we go to their main website [https://kiro.dev/cli/](https://kiro.dev/cli/), we are greeted with a Curl Bash aka "Trust me bro" shell script:

```
curl -fsSL https://cli.kiro.dev/install | bash
``` 

we're not going to do that instead lets download the script and inspect:

```
wget https://cli.kiro.dev/install
```

then we can open up the script, it's the usual arch and os probing as well curl/unzip/wget dep checks as well making sure there is enough disk space.

We can skip most of this and just search for `download_url` which is made up of:

* `channel_base_url`
* `release_dir`
* `filename` which itself is constructed from `{ZIP_PACKAGE_NAME}-{arch}-linux.zip`

if we follow the script, assuming you're on Linux and using x86-64 then the final download url is:

```
https://prod.download.cli.kiro.dev/stable/latest/kirocli-x86_64-linux.zip
```

after grabbing this using curl/wget, we can unzip the folder:

```
unzip kirocli-x86_64-linux.zip
```

this gives us the following:

```
kirocli/
```

both `q` and `qchat` are just shell script wrappers that call into the actual binaries, but holy smokes 210MB for a CLI??!
